Quand le ping répond mais que SSH ne répond plus

Ludovic Suy — administrateur d’infrastructures sécurisées · homelab documenté

Depuis Paris, deux machines de mon lab répondaient au ping mais refusaient toute connexion SSH. Sans prise programmable pour couper l’alimentation à distance, il a fallu se déplacer. Voici ce que j’ai mis en place ensuite.

Le problème

Le tunnel WireGuard était sain. Le ping vers les machines passait. Pourtant, le port 22 timeout. Impossible de se connecter pour diagnostiquer ou redémarrer. Les sites servis par l’une des machines continuaient de répondre, preuve que tout n’était pas éteint. Seulement, le système ne répondait plus aux connexions SSH.

Ce type de hang silencieux est courant sur des machines headless. La machine est vivante au niveau réseau, mais le userspace est gelé. Sans écran ni prise programmable (PDU), la seule solution immédiate est de se déplacer pour redémarrer physiquement.

La solution : le watchdog matériel

Après les reboots sur place, j’ai activé un watchdog matériel sur les deux machines.

Le principe est simple. Le hardware contient un compte à rebours. Un petit programme (le daemon watchdog) doit régulièrement lui écrire pour le remettre à zéro. On appelle ça « caresser le timer ». Si le système hang et que le programme ne peut plus le faire, le compte à rebours arrive à zéro et le matériel force un hard reboot. La machine revient toute seule.

Sur une machine Intel, c’est le module iTCO_wdt. Sur la GX10 (ARM), c’est le SBSA Generic Watchdog. Dans les deux cas, le timeout est réglé à 60 secondes. Le daemon écrit toutes les 10 secondes. Si personne n’écrit plus, le matériel reboot.

Pourquoi ce n’est pas un gadget

C’est une pratique standard en production pour les machines distantes ou headless. Les administrateurs l’utilisent depuis longtemps sur les serveurs, les appliances, les routeurs. Ce n’est pas une solution de confort : c’est un filet de sécurité contre les hangs silencieux qui obligent à se déplacer.

Une PDU (prise programmable) reste utile pour les cas extrêmes où même le watchdog ne suffit pas. Mais le watchdog couvre déjà la majorité des situations où le système est gelé sans être totalement mort.

Ce que ça change concrètement

Aujourd’hui, si l’une de ces machines entre dans le même état, elle se redémarrera toute seule au bout d’une minute. Je pourrai me reconnecter depuis Paris sans avoir à me déplacer. Le déverrouillage LUKS distant reste disponible sur la machine qui en a besoin.

Ce n’est pas la solution à tous les problèmes. C’est simplement celle qui évite de revivre exactement le même incident.
