Notes de lab

Deux origines.
La vitrine n’est pas l’atelier.

16 septembre 2026 · Ludovic Suy · Horus AIS

Un nom de domaine n’oblige pas à exposer la machine qui construit le lab. Après avoir validé un atelier derrière OPNsense — serveur web, tunnel, incidents, documentation — j’ai sorti l’enseigne du tuyau. HTML, CSS, JavaScript de navigateur : ça vit sur Cloudflare Pages. L’atelier reste chez moi.

D’abord le lab, pas la comm

Je viens du terrain. Titre TSSR, puis un homelab mené comme on mène une infra qu’on devrait pouvoir expliquer : pare-feu OPNsense, règles par défaut refusantes, zones séparées, une machine dédiée pour servir des fichiers web derrière un WAF, un tunnel Cloudflare pour ne pas ouvrir les ports 80 et 443 sur la box.

Le fonctionnement a été validé en local, puis exposé proprement. Il y a eu des incidents. Ce n’est pas un aveu de faiblesse. C’est le matériau. Chaque coupure, chaque cache DNS qui répète un « n’existe pas », chaque service qui redémarre mal, ça devient une fiche, une cause, un correctif. On documente en parallèle. Sinon on oublie, et on recommence.

Le tunnel reste le bon outil pour ce qui doit vivre dans l’atelier : pages de travail, noms d’expérimentation, ce qui a le droit de tomber quand la tour s’arrête. Ce contrat-là est clair.

Le problème n’était pas le tunnel

Le problème, c’était de faire porter le nom de la société par le même tuyau. Une vitrine en HTML / CSS / JS n’a pas besoin d’un daemon chez soi. Elle a besoin d’une origine statique, versionnée, reproductible. Si l’atelier s’arrête — maintenance, électricité, incident — la porte publique n’a aucune raison de s’éteindre avec.

D’où le split, joué et vérifié :

  • Enseigne — horus-ais.com et www — Cloudflare Pages, dépôt Git.
  • Atelier — sous-domaines de travail — le tunnel existant, un seul, vers le WAF local.
  • Mail — MX chez l’hébergeur de messagerie. On n’y touche pas pour publier une page.

Pages n’est pas Workers

Sur le tableau de bord Cloudflare, les deux produits partagent un menu. Ce n’est pas un détail cosmétique.

Pages prend un dépôt de fichiers et le sert au bord du réseau. HTML, feuilles de style, JavaScript exécuté dans le navigateur : ça entre dans ce contrat. Un git push sur la branche principale republie. On peut accrocher ensuite son vrai nom de domaine — d’abord www, puis l’apex — pour que le visiteur reste sur horus-ais.com, pas sur une adresse technique *.pages.dev.

Workers, avec Wrangler, c’est l’exécution côté serveur. Du JavaScript qui tourne chez Cloudflare, pas dans le navigateur. Utile le jour où on a vraiment de la logique à faire tourner au bord. Ce n’est pas le bon assistant pour déposer un dossier de pages statiques. Si l’écran propose npx wrangler deploy et un jeton d’API, on n’est plus dans Pages. On revient en arrière, on prend l’onglet Pages, preset « None », commande de build vide ou exit 0, répertoire de sortie /.

Les deux outils resteront dans le paysage. On ne les confond pas pour aller plus vite.

L’ordre compte

On ne débranche pas le nom de domaine du tunnel avant que Pages le serve. On ne bascule pas www et l’apex dans le même geste. Un nom à la fois : si l’un casse, l’autre tient. On relit les MX après l’apex. Le mail n’est pas un « détail DNS ».

Côté atelier, le tunnel garde uniquement ce qui doit pouvoir tomber. Côté enseigne, plus aucune dépendance à la machine allumée sous le bureau.

Cette page est la démo du propos. Elle est servie par Pages. L’atelier peut être éteint : vous êtes encore en train de la lire.

Ce que ce texte n’est pas

Ce n’est pas une offre commerciale, ni le mode d’emploi d’un lab privé, ni une plaquette d’agence bouclée. L’accueil du site reste une première version. Je le sais. Je ne demande pas qu’on juge une vitrine en chantier comme un catalogue.

C’est un choix d’architecture, écrit après l’avoir joué. TSSR, homelab, documentation en parallèle. Si vous montez une infra chez vous et que vous vous demandez où faire vivre le nom de domaine : le tunnel n’est pas la seule réponse, et ce n’est pas la bonne pour tout.
